## 3. Client — store the return on navigation

- [ ] 3.1 In `pkg/src/client/index.ts`, add a delegated click listener on `document` that matches links whose path is `<base>/apps/<id>` (base read from `document.documentElement.dataset.appBase`, falling back to the path prefix up to the first `/apps/`), and synchronously stores `location.pathname + location.hash` under `sessionStorage` key `kody-os:return` before the navigation proceeds. The handler MUST NOT prevent default, stop propagation, or change the destination; middle-clicks and modified clicks are left to the browser and simply store nothing extra. All storage access is wrapped in try/catch with a `typeof sessionStorage !== 'undefined'` guard, and any failure behaves as "no stored value"
- [ ] 3.2 In the same listener, intercept modal-tile clicks (href carrying `?touch=1`): prevent the default navigation, fetch the same URL with `format=json` appended (`credentials: 'same-origin'`, same-origin guard as the existing fast path), and on a JSON `{ ok: true }` response set `location.hash = 'app-<id>'` to reveal the overlay. On any fetch failure, non-JSON response, or `{ ok: false }`, fall through to the native touch URL (plain navigation, server 303s to the overlay as today). The intercept MUST NOT run for non-modal tiles

## 4. Client — apply the return on the app page

- [ ] 4.1 On load in `pkg/src/client/index.ts`, when a `section[data-app-id]` is present, implement the return reader: read `kody-os:return`, validate it with a client-side validator mirroring the deleted `safeNextPath` rules (leading `/`, no `//` prefix, no `\`, no `://`, no CR/LF, must start with the `data-app-base` value), plus the fragment guard (a `#app-<id>` fragment is kept only when `<id>` equals the current app id, otherwise the bare path is used if valid). On any validation failure, storage failure, or missing value, leave the server-rendered close box untouched (Home)
- [ ] 4.2 With a valid value, set the titlebar close box (`.os-titlebar a.os-box`) `href` to it and its `aria-label` / `title` to Apps when it equals the Apps path, Home when it equals the home path, and Back otherwise — the same labelling rule the server used
- [ ] 4.3 Legacy migration on the same load: when the URL carries a `from` query value, validate it under 4.1; when valid it wins over the stored value, is written to storage, and is then removed from the visible URL with `history.replaceState` (other query parameters preserved). When invalid it is stripped from the URL and ignored. This migration runs only on app pages, not on the dashboard or Apps page
