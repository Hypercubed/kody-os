# Tasks

Phases land in order: 1, then 2, then 3. No task in this file commits, pushes, or publishes anything. No release/publish steps are in this plan — the owner decides when to release once there are enough changes.

## 1. Remove the gate

- [ ] 1.1 Remove the gate from `pkg/src/app.ts`: `fetch()` SHALL call `dispatch()` unconditionally, with no visitor check, no role check, and no `metaGetCurrentUser` call. Delete `lockedPage()`, the `authPath` field from the chrome (`Chrome` / `shellChrome` options, `authLabel` default), and the `auth.ts` import. The footer SHALL NOT report an auth path. Unknown routes SHALL still return 404 inside the full chrome with plain "Not found." text.
- [ ] 1.2 Delete `pkg/src/auth.ts` in full (`isKodyOwnerVisitor`, `isKodyVerifiedVisitor`, `parseVisitorHeader`, `visitorHeader`, `isMockTarget`, `AccessCheck`, `AuthPath`, `authPathFor`). No replacement auth helper SHALL be added. Grep SHALL find no remaining import of `./auth.ts` and no remaining reference to any of those names in `pkg/src/`.
- [ ] 1.3 Delete `tests/owner-check-harness.ts`. Grep SHALL find no gate references (`isKodyOwnerVisitor`, `isKodyVerifiedVisitor`, `via kody`, `locked`, `device gate`, `owner gate`) in `tests/` except explicit denial cases for retired behaviour, if any are kept — record any that are kept and why.
- [ ] 1.4 Update docs to state the Kody permission model (Decision 4): the root `README.md`, `pkg/README.md`, `pkg/AGENTS.md`, `pkg/docs/setup.md`, and the repo-root `AGENTS.md` (where it describes the gate) SHALL all say access is granted/revoked in Kody itself (Use / `app:execute` on the app), the shell performs no access check, package visibility and `internet_visible` are independent toggles, and turning `internet_visible` on exposes the app to anyone on the internet with no shell gate left. `pkg/docs/setup.md` SHALL carry the grant/revoke steps with a verification step, and SHALL NOT describe a shell-side denial, locked page, or owner check as deciding access. MCP exports SHALL be described as governed by Kody's `package:execute` / org access, unchanged by this change.
- [ ] 1.5 Update any other doc that describes the gate as the way in (grep `device gate`, `via kody`, `locked`, `owner-only` across `pkg/docs/`, `pkg/.agents/skills/adding-an-app/SKILL.md`, and `pkg/docs/style-guide.md`): each SHALL be corrected to the permission model or have the gate wording removed, and the change SHALL record what was touched. No doc SHALL claim the shell enforces owner-only access after this change.
