# Design: settings-page-redesign

## Context
See proposal.md (Why). The current Settings bundle (`pkg/catalog/settings/index.html`, a stateless bundle) renders six sections — Background, Name, Title, Icon, Pages, Reset all — each as an `st-field` block with a "Current: X (source)" line, forms, and buttons. The theme read route returns `defaults` / `override` / `effective`; the bundle shows the effective value and its source. The shell already implements `ui.menuBar` (the registry validates it as a boolean, preserves it through canonicalization, and the menu bar renders menu-app links for apps with `menuBar: true` that are not hidden; no shipped app uses it today). The mockup (`settings-redesign-mockup.html`) is the agreed layout.

## Goals / Non-Goals
- Goals: a Settings page with one clear structure, a visible customized-vs-default cue, one primary control per setting, and a menu-bar link when installed.
- Non-goals: changing the theme fields, routes, or capability; changing the shell menu-bar mechanism; adding a grid or SVG editor; changing any other app.

## Decisions
1. **Section titles use the shared black bar.** Each section opens with `.os-section-title` (black background, white uppercase 14px bold, letter-spaced), the shared section-title class. This gives the page one structure instead of six identical h3s.
2. **The current value is a readout with a badge.** Each setting shows "Now: …" plus a badge: `default` (plain, bordered) when the value comes from the file, `changed` (inverted, black background, white text) when an override exists. The badge replaces the parenthetical "(file default)" / "(override)" source text. The badge is the customized-vs-default cue, visible at a glance.
3. **One primary control per setting; Reset is quiet.** Background uses a segmented Desk/Paper control (active = inverted, the same cue as the News tab and the Apps Edit toggles). Name and Icon are one labeled field plus one Save button. Reset is a small underlined text link under each setting, not a full button; "Stock mark" is a quiet link too. The page stops being a wall of identical buttons, and the destructive action stops looking like the primary one.
4. **Name stays, Title goes.** Only one of the two is needed. The page keeps Name and drops the Title field entirely (no Title input, no Title reset, no Title readout). A blank title already means "show the name", so the Title field duplicates Name. The theme title override remains settable via the file or an agent; only the bundle field is removed.
5. **Pages use the Apps Edit toggle button.** Help and About each get the same icon-only toggle button as the Apps Edit page (`.edit-toggle-btn`, 48px square, the eye-off SVG icon, `role="switch"`). "On" (flat, inverted, `.edit-toggle-btn-on`) means hidden, exactly as in Apps Edit: the button is plain when the page is shown and inverted when it is hidden. The toggle submits as a plain GET form with a hidden `want` field carrying the opposite value, so no JavaScript is required — the same mechanism as the Apps Edit toggles. The current state lives in the caption and badge, not in a second button.
6. **Settings appears in the top menu bar when installed.** The Settings definition sets `ui.menuBar: true`. When installed, the shell adds a "Settings" link to the top menu bar (after Apps, alphabetical by label, alongside the other menu-app links). The link is excluded when the app is hidden and removed when the app is uninstalled. No shell code changes: the mechanism already exists (the registry validates and preserves `menuBar`; the menu bar renders menu-app links for non-hidden apps with the flag). No shipped app uses the flag today, so Settings is the first.
7. **Wiring and constraints are unchanged.** Core controls remain plain GET forms to `/theme/<app>` (no POST, no JavaScript required); bundle JavaScript MAY enhance in place with `format=json`, never required. The bundle satisfies the existing bundle constraints (ES2019 script, one inline `<style>`, inlined assets only, zero external links, system fonts, high-contrast black-on-white, 48px minimum tap targets, 256 KiB cap). No grid editor or SVG editor. The custom-grid / custom-mark notice behavior is unchanged (show the notice instead of an editor for that field, while still offering desk/paper or glyph/stock/reset to replace it).
8. **Version.** The Settings app's `catalogVersion` goes 2 → 3 for this change (one increment for the bundle + definition change). The package version decision is deferred to publish (owner applies it).

## Open Questions
- None. The layout is settled by the mockup.
