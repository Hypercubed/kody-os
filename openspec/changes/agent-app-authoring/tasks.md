## 2. Phase 2 — Shell-provided framework (select, provide, port)

- [ ] 2.1 Selection evaluation: judge each candidate — Svelte (plain compiler only, not SvelteKit; Svelte 5 first, Svelte 4 branch only if 5 fails the gates), Custom Elements / Web Components (vanilla platform only; Lit not evaluated in this task; light-DOM and shadow-DOM variants), the microframeworks re:dom and VanJS (each separately, no other microframeworks in scope), and Alpine.js (directive-based; `x-data` scopes, `Alpine.data()`/`Alpine.store()` namespacing, `alpine:init` registration timing, `Alpine.start()` ownership) — on provision feasibility and isolation FIRST: can the shell load it once per page in all placements, can it be instantiated per app section with no shared mutable state, do top-level names / registry names / styles stay section-scoped, and does a failure in one section stay contained; then on the existing gates: size (including any shared code, against the 256 KiB bundle cap where per-app code remains; measure the actual Alpine build shipped, size claims conflict), ceiling compliance (after downleveling for Svelte, as written otherwise, including Alpine directive expressions and `new Function` evaluation), harness scenarios (ordering, staleness, fallback) against real shell markup via `kody dev` with state synced through the span/`act()` adapter, and a Scribe-engine probe. Record a selection decision with evidence per candidate; no selection without all gates passing, and a reject records why (including whether the failing ground is generic to provision, recorded once). The selection record also notes the current A2UI status (watch item per the design Context, not a candidate) so the decision is made with it current.
- [ ] 2.2 Provision: implement shell provision of the selected framework (mechanism per Open Question 2: asset, inline client code, or import map) together with the shell-bridge adapter instantiated per app section (initial-state read, paint/sync, observer adoption with sequencing guard, single-flight queue, capture-phase form claim scoped to the section, action-base resolution, fetch-with-fallback, `DOMContentLoaded` discipline), with the provided surface versioned and the isolation properties from the `shell` spec demonstrated on a multi-section page before any app ports to it
